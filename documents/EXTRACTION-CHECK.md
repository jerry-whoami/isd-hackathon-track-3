## Variants tried for the Anexo A table (H1)

Per the brief, I built a throwaway variant harness first (in the session
scratchpad, not in the repo) before committing to a design:

1. **Plain HTML `<table>`, `border-collapse: collapse`, default browser
   column sizing, no fixed widths, no `white-space: nowrap`.** Rendered via
   the same Chrome command as the real documents, extracted with
   `pdftotext -layout`. Result: **passed immediately** — every row, including
   the longest one (`Albatros Holdings Ltd. | Tortola, Islas Vírgenes
   Británicas | 45`), came out as exactly one line, columns aligned by
   `pdftotext`'s own spacing heuristic. No row was split across lines or
   merged with another row.

I did not need to try the fallback alternatives the brief anticipated (fixed
column widths, a `|`-separated monospace block, `white-space: nowrap`)
because the plain table already satisfied H1 on the real, full-length
document (prose + table + injection). Kept the simplest option per the
brief's instruction ("keep the simplest one that passes"). One caveat worth
recording: in the **hostile** carta, `pdftotext -layout` stretches the
column gaps far wider than in the clean carta (because the very long,
invisible injection line after the table is the widest line on the page and
`pdftotext` sizes columns to the page's line-position histogram). This is
purely cosmetic whitespace — it does not split or merge any row — but it is
a visible artifact if anyone diffs the raw `.txt` files, so I'm flagging it
rather than silently normalizing it away.

## 2026-09-10 — Removed in-document "fictitious" markings (T10 finding)

Spike T10 found that the extractable banner "DOCUMENTO FICTICIO — PREPARADO
PARA DEMOSTRACIÓN. Nombres, sociedades y personas ficticias, creados
únicamente para este ejercicio." and phrases like "sociedad ficticia" cause
the model reviewing the documents to treat the hostile bid as a harmless
exercise rather than a real filing: attack obedience on the hostile bid fell
from 8/10 to 1/10 when that wording was present in the extracted text.
Decision: the fictitious nature of these documents will be declared only in
the repository README (written separately), never inside the documents or
corpus themselves.

  from `scripts/generate-documents.mjs` (and therefore from all four
  generated `.html`/`.pdf` documents), plus the equivalent header comment.

  inscrita" in both `propuestaHtml()` and `cartaHtml()`.

  ... ficticia" / "para este ejercicio" comment blocks and the
  `fictitious_notice:` field from `corpus/procurement/pliego.yaml` and
  `corpus/onboarding/manual-dd.yaml`.
- The " — entidad ficticia" / " — firma ficticia" suffixes on the `entity:`
  and `firm:` fields in those same two YAML files.

Everything else (names, clauses, values, injections, tables, citations) is
